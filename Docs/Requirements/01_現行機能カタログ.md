# 現行機能カタログ

## 1. 製品の目的と利用者

RINKAN UMISは、林間学校等の記録班が、SDカードやカメラメディアから写真・動画・RAW・音声を取り込み、撮影日とシーンへ仕分け、統一名でアーカイブし、その後に良い素材を「選別」フォルダへ集めるためのツールです。

文書上の対象は、PC操作に不慣れで、現場の時間制約が強い利用者です。UXの中心は「迷わない」「途中で止まらない」「一目で現在地が分かる」です。[CLAUDE.md](legacy-source/CLAUDE.md:8)

主要な業務フローは次です。

```text
メディア接続
→ 読み込むfolderを決定
→ 撮影者・カードID・会場・日目を確認
→ サムネイルで素材を選択
→ シーンへ仕分け
→ リネームしてアーカイブへ取り込み
→ 取り込み済みsceneを開く
→ 良い素材へ星を付ける
→ scene内の「選別」folderへ複製
```

## 5. Copy／Renameの利用者向け仕様

### 5.1 Defaults

- destination: `~/Rinkan_UMIS_Archive`
- location: 第1〜第8、高校
- card: 01〜05
- photographer: 田中、山田、高橋
- selection folder: `選別`
- scene numbering: ON
- date: ON、`%m%d`
- card ID: ON
- photographer: ON
- location: OFF
- sequential rename: OFF
- detailed log: ON
- hover scrub: ON

### 5.2 Output folders

```text
Destination/
  Category/
    DNN_SceneName/
      RenamedFile
      選別/
```

photographer folderは作りません。設定に残るcategory／scene／photographer folder toggleやfolder orderは実処理へ反映されません。

### 5.3 Filename

有効なcomponentを設定順に`_`で連結し、最後にoriginal filenameまたはsequenceを付けます。

既定順:

```text
Location_Scene_Date_CardID_Photographer_OriginalName
```

locationは既定OFFです。scene numbering ONなら`101_会場到着`形式です。dateは一部画像でEXIF DateTimeOriginal、それ以外はmtime fallbackです。sequence ONなら全run共通で`0001`から始まり、scene／categoryごとにはresetしません。

### 5.4 Current copy phases

1. source read permission
2. destination write permission
3. free space
4. source全件をhome tempへcopy
5. tempからdestinationへrename copy
6. temp／final size比較
7. temp削除
8. notification／history／format許可

機能の詳細と不具合は [02_現行アーキテクチャとデータ.md](02_現行アーキテクチャとデータ.md) と [03_不具合_性能_安全性監査.md](03_不具合_性能_安全性監査.md) に分離しています。

## 6. セレクトモード

### 6.1 Library／Scene navigation

destination配下のcategory foldersを横断し、同名scene folderを1 sceneとして集約します。

- day filter: `すべて`、実在する`その他`、1〜4日目
- each scene row: file count
- `すべて`は全file表示ではなく、全dayのscene一覧
- scene未選択時: `シーンを選択してください`
- scene選択時: 全categoryの同名sceneを再帰scan

[library scan](legacy-source/rinkan_umis_v1.1.103.py:4322) / [scene click](legacy-source/rinkan_umis_v1.1.103.py:4922)

### 6.2 Center toolbar

- bulk selection mode ON／OFF
- `選択解除`
- sort
- thumbnail size
- grid／list

常時guide:

> 操作: クリック=プレビュー ／ S=選別に追加・解除 ／ Space=拡大表示 ／ ←→=前後移動

### 6.3 Two selection concepts

セレクトcardは別の2状態を持ちます。

- blue check／`selected`: scene move対象
- star／`is_selected_for_edit`: `選別`へcopyする対象

通常clickはfocus、starまたはS keyでpickします。Shift／right click／bulk selectionは主にmove selectionです。初心者には区別しにくいため、Swift版はmacOS標準selectionとstarを明確に分けます。

### 6.4 Selected／Unselected groups

`選別`folderに同名fileがあれば、元側をhideし、`選別済み`groupに選別側だけを表示します。判定は内容hashではなくfilename一致です。

### 6.5 Star and commit

star toggle:

- grid star
- list star
- focused fileでS

footerは`n件をセレクトに追加`、0件でdisabledです。実行時に各category／sceneの`選別`へ同名copyし、完了後同sceneをrescanします。[select copy](legacy-source/rinkan_umis_v1.1.103.py:7176)

現行不一致:

- 既存同名skipも`copied_count`へ加算
- `_select_locked`は読取だけで設定なし
- 選別済みは非表示ではなくgroupに残る
- 赤いCancelは現行copy threadへ届かない

### 6.6 Inspector

- 16:9 preview
- filename
- size
- duration
- category
- created date
- captured date
- modified date
- movie resolution／codec／frame rate
- `未選別`／`選別待ち`／`選別済み`
- `別のシーンへ移動`

日付の実意味は揃っていません。

- 表示`作成日`: `st_ctime`
- 表示`撮影日`: scan時mtime string
- 表示`更新日`: current mtime
- `作成日順`: macOS `st_birthtime`

新版では`撮影日時（metadata）`、`file作成日時`、`file更新日時`を明示します。

### 6.7 Move to another scene

flow:

1. move selection
2. `移動先のシーンを選択`
3. 1〜4日目tab
4. scene
5. `シーン移動の確認`
6. `実行`

現行動作:

- physical fileを移動
- filename中の旧scene stringを全置換
- selected folderを維持
- 元fileを動かす場合、選別copyも移動
- cacheも移動
- 新sceneへ画面切替

制限:

- `その他`がmove先にない
- collision確認なし
- undoなし
- partial failureでrollbackなし
- snackbarはsuccess数中心

## 13. Format／Hide／Eject

### 13.1 Format

- macOS: `diskutil eraseVolume ExFAT`
- label: ASCII alphanumeric／underscore、11文字

- emergency: 任意candidateを許可
- 3-step confirmation
- 128GB warning
- unassigned／skipped／failed warning

安全性は監査文書を参照してください。Swift初版では機能を外す案を推奨します。

### 13.2 Hide media

- confirmation
- `excluded_source_drives`へdisplay string保存
- current mediaならfiles、assignment、identity、dayもclear
- restoreはSettings > List managementの奥

新版ではmedia pickerにもrestoreを置きます。

### 13.3 Eject

現行sequence:

1. media generation cancel
2. 最大3秒wait
3. preview／audio／video stop
4. `diskutil eject`
5. 失敗時2秒後retry
6. failure dialog: details／force／retry／close

ただしUI stateをeject前にclearします。新版は`.ejecting`stateを表示し、success callback後だけremoveします。

## 14. 日跨ぎ確認

前回作業日が今日と違い、前回dayが1以上なら、起動2秒後とmedia load開始時に`作業日の確認`を出します。

- `現在のまま`
- `その他`
- 1〜4日目

現行はdialogを出す時点で`last_worked_date=今日`を保存し、Esc generic closeではresolve callbackを呼びません。media load flowのscan continuationを失い、その日は再確認されない可能性があります。新版は選択後だけ日付をcommitし、Escを明示的なdecisionへmapします。
